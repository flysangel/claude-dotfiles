# 驗收情境：sdd-grill

在已導入 Spec Kit 的暫存專案，把 `home/skills/sdd-grill/` 複製到 `.claude/skills/`。

| # | 情境 | 預期 |
|---|---|---|
| 1 | 一句模糊的專案描述 | 一次只問一題，附建議答案與理由 |
| 2 | 答案能從專案查到 | 自行查閱，不問維護者 |
| 3 | 回答與先前決策矛盾 | 指出矛盾並要求取捨 |
| 4 | 回答含糊 | 追問到能判斷對錯為止 |
| 5 | 維護者確認決策摘要 | 才寫入 constitution，並為每個功能各寫入一份 spec |
| 6 | 中途要求結束 | 得到已決定與未決定事項的摘要，進度已保存，沒有寫入 constitution 或 spec |
| 7 | 問到技術選型 | 記錄為留給 plan，不在此決定 |
| 8 | 上次討論已中斷，再次執行 | 列出已決定事項，由維護者選擇接續或重新開始 |
| 9 | 文件已寫入 | 進度檔已刪除 |

另外確認：

- `.specify/sdd-grill-progress.md` 列在 `.specify/.gitignore`，從未進入 git。
- 多個功能時，編號依相依順序，`feature.json` 指向第一份。
- 接續時專案已有變更，會先提示。
- 產出沒有待釐清標記，也沒有維護者未確認的規則，流程止於 spec。
- 沒有 `.specify/` 時提示先執行 `/sdd-init`，不寫入任何內容。
- 文件語言跟隨專案既有文件，沒有時用繁體中文。
